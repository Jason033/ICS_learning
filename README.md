# 知識航線：可擴充的個人學習網站

**公開網站：** https://jason033.github.io/ICS_learning/  
**GitHub 儲存庫：** https://github.com/Jason033/ICS_learning  
**發布來源：** `main` 分支的 `/docs`，GitHub Pages 已啟用。

這個專案讓使用者依主題學習通訊、程式與設備知識，目標是逐步具備維護系統與分析故障的能力。每個主題有自己的章節順序；只有內容確實相關時才連到另一個主題。未來可以加入任何新領域，不必放進通訊系統的分類。

網站已完成可使用的第一版。首頁列出 16 個獨立主題；〈電腦網路〉10 篇與〈Wireshark〉8 篇教材已完整可讀，另外 4 篇仍是可閱讀的入門樣本，其餘清楚標示「規劃中」。教材有學習目標、白話說明、圖解、練習與可展開的解答。教材狀態與實際內容一致；「列在目錄上」不等於「教材已完成」。

## 已確認的需求與教材界線

- 主要給使用者自己使用；內容從基礎循序教起。使用者對 IP、Port、TCP／UDP、Socket 已有部分理解，但還需要把概念串成整體。
- 使用者指定需求並檢視內容，助手負責製作與維護。第一版採圖文教材、練習與解答。
- 目前學習範圍涵蓋網路、Socket、Wireshark、VoIP／音訊、Ozeki API、ICS／RCS 程式閱讀、RS-232、無線電、PTT、可靠性、Windows／Linux、衛星與多鏈路、DSP／SDR、資安及綜合故障分析。詳見 [課程地圖](課程地圖.md)。
- 教材區分通用原理、標明假設的教學例子，以及使用者提供並確認過的實際系統資訊。更新的 `對話.txt` 用作工作背景；裡面先前助手推測的呼叫順序或設備行為，不會被寫成已證實的公司架構。
- 新增大主題時，沿用網站版型並建立自己的章節目錄；不要求修改其他主題的教材或順序。

## 目前可以怎麼使用

進入首頁後選一個主題，從該主題自己的目錄挑選章節。讀完圖文可先回答練習，再展開解答。讀畢可以按「標記為已完成」；完成紀錄只保存在目前瀏覽器，換裝置或清除瀏覽器資料後不會保留。首頁搜尋可找主題或章節名稱。

〈電腦網路〉已完成一套約 **400 分鐘、10 篇**的教材，從最初的請求與回覆，依序學位址端點、Ethernet／MAC／ARP／VLAN、子網與路由、TCP／UDP、DNS／DHCP／NAT、單播／廣播／群播、MTU／QoS、效能指標，最後用整合故障案例練習定位。每篇有目標、白話說明、圖解或表格、至少 5 題練習與解答、重點回顧和公開技術來源；第一篇另有可在自己電腦操作的本機小實驗。教學位址、封包與設備情境明確標成模擬，沒有宣稱是公司系統。可從[網路主題頁](https://jason033.github.io/ICS_learning/#/topic/networking)依序進入。

〈Wireshark〉也已完成約 **355 分鐘、8 篇、48 題練習**的教材，從安裝與開檔、三個檢視區塊、兩種篩選、Follow Stream 與統計視窗，進到 TCP 故障、SIP／SDP、RTP 分析和封包對時。每篇都連到對應的[合成教學 PCAP](docs/assets/labs/README.md)，可在桌面 Wireshark 直接開啟；也有自製三區塊示意圖。PCAP 全由程式產生，不含公司流量。可從[Wireshark 主題頁](https://jason033.github.io/ICS_learning/#/topic/wireshark)進入。

Ozeki API、RS-232、無線電、PTT 四個主題各有一篇**入門樣本**，頁面會明確標示；其餘章節仍是規劃中。這些主題可以獨立進入，不以學完整個網路主題為前提。

## 本機開啟

在本資料夾執行：

```bash
python3 -m http.server 8000 --directory docs
```

Windows 若使用 Python Launcher，可改用 `py -m http.server 8000 --directory docs`。接著在瀏覽器開啟 `http://localhost:8000/`。網站使用本機伺服器載入 JSON；直接雙擊 `index.html` 可能受到瀏覽器檔案存取限制。

## 放到 GitHub Pages

網站使用原生 HTML、CSS、JavaScript 與 JSON，沒有套件安裝或建置步驟。`docs/` 是可直接發布的網站目錄。

1. 若要建立另一份網站，先建立 GitHub repository，將本專案資料夾中的檔案放在儲存庫根目錄。
2. 在 repository 的 **Settings → Pages**，選擇 **Deploy from a branch**、`main` 分支及 `/docs` 資料夾，儲存設定。
3. 等待 GitHub 顯示網站網址，再用瀏覽器測試首頁、主題頁與章節頁。專案型 Pages 網址一般會包含 repository 名稱；本站採雜湊網址，章節連結也能在該路徑下運作。

本專案已發布在上方所列網址。後續更新公開內容前，請檢視教材與檔案，避免將公司或廠商非公開資料放進公開儲存庫。GitHub Pages 的[官方發布說明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)可作設定參考。

## 怎麼新增或修改教材

網站內容分成目錄、各篇教材與可重用資源：

```text
docs/
├─ index.html                網站入口
├─ styles.css                共用外觀
├─ app.js                    導覽、教材顯示與本機完成紀錄
├─ content/
│  ├─ catalog.json           所有主題與章節的清單、順序及狀態
│  └─ lessons/
│     └─ 主題代號--章節代號.json   每篇可閱讀教材
└─ assets/
   ├─ labs/                  可下載的 Wireshark 教學 PCAP
   └─ diagrams/              自製示意圖
```

- **新增主題**：在 `catalog.json` 的 `topics` 清單加一個主題，設定不重複的 `id`、標題、說明與自己的 `chapters`。不需要修改現有主題。
- **新增章節**：在所屬主題的 `chapters` 加入章節資訊，並建立 `docs/content/lessons/主題代號--章節代號.json`。教材完成後把章節 `status` 設為 `ready`；仍在規劃則設為 `planned`，不建立空白頁。
- **章節格式**：參照現有 JSON，包含 `intro`、`goals`、`sections`、`exercises`、`recap`、`sources`。完整教材可加入 `plan` 學習時間安排與 `resources` 下載檔。段落可使用 `paragraphs`、`flow`、`bullets`、`steps`、`table`、`code`、`image`、`note`；網頁會自動套用共用版型。目錄中的 `contentType` 設為 `full` 或 `sample`，與教材完成程度一致。
- **保持連結穩定**：`id` 不跟隨顯示順序變動。調整章節位置只移動清單項目，不更改既有 `id`。
- **交叉引用**：只在教材確實需要其他主題的概念時加入連結或簡短提示。每個主題的入門章節應能獨立閱讀。

## 設計與驗證方式

基準是使用者已認識部分名詞，但尚難把它們連成完整流程。網路主題先用一次請求作共同觀察例子，再分章改變一個重點：端點、鏈路、路由、傳輸、輔助服務、群播、封包大小與效能。每篇用模擬案例比較「正常／異常」或「觀察前／後」，以練習檢驗讀者能否說清楚證據支持什麼、還缺什麼，以及下一步要查哪裡。最後一篇把前面所學放進多組整合故障案例。Wireshark 主題以同一批已知封包作基準，逐章改變觀察工具：列表／細節、篩選、串流、統計、SIP／RTP，再比較「能看到的封包」與「程式或設備是否完成」之間的證據差距。

目前沒有完成學習成效實驗，也沒有真實公司系統的測試結果。10 篇網路教材的驗證標準是讀者能正確說出請求與回覆路徑、判讀端點與下一站、區分傳輸確認與應用成功，並在故障案例中選出下一個證據；56 題練習提供自我檢查，尚待使用者實際學習後回饋。Wireshark 的驗證標準是讀者能自己開啟三份 PCAP、找出方向與端點、用正確篩選定位案例，並對 TCP ACK、SIP 200 OK、RTP 序號缺口提出不超出證據的結論；48 題練習提供自我檢查。其餘四篇仍是第一版樣本。Ozeki 具體 API 需依使用版本核對，設備狀態、RS-232 接線與 PTT 行為需依授權文件及實測確認。Wireshark、SDK 和硬體實驗需要相應的桌面工具或測試環境，網頁提供步驟、說明與解答。

開發檢查涵蓋 JSON 解析、教材與目錄對應、每篇學習時間與練習數、表格欄數、資源檔存在、JavaScript 語法、頁面導覽及本機伺服器供檔；Wireshark 教學 PCAP 另以獨立程式驗證檔案格式、時間、IP／TCP／UDP checksum 與預期封包。本機小實驗也以 8765 成功、8766 失敗、停掉服務後 8765 失敗的結果核對。另以本機 Chrome 檢視桌面與窄視窗教材頁。GitHub Pages 已成功建置本次 Wireshark 更新；公開首頁、目錄、八篇 Wireshark 教材、示意圖與三份 PCAP 均可讀取，且與本機提交檔案逐位元組一致。先前十篇網路教材也已完成公開讀取檢查。這個開發環境沒有安裝 Wireshark 桌面程式，三份 PCAP 已完成格式與欄位的獨立檢查，但尚待使用者在自己的 Wireshark 版本打開，確認畫面解析與操作步驟。學習成效及使用者常用手機的實際閱讀感受也尚待回饋。
