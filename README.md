# 知識航線：系統維護與除錯學習網站

[打開學習網站](https://jason033.github.io/ICS_learning/) · [GitHub原始碼](https://github.com/Jason033/ICS_learning)

這是給個人循序學習的長期專案。目標是先建立完整基礎觀念，進而讀懂公司程式的呼叫、資料、事件與狀態，能解釋故障如何產生、找證據、修正並重測。主題各自獨立，沒有關聯的內容不硬接在一起；後續可新增主題與章節。

## 為什麼重編第二版

第一版的問題是正文過於簡略：83篇正文中位數僅1,145非空白字元，卻在目錄列出總共4,220分鐘。段落、範例或測試檔存在，不代表基礎已教完整。使用者明確要求全面重寫，並澄清核心缺口是基本內容，不只是缺實作。

第二版以C#／.NET為主、Python為輔助，先把「為何需要、定義、逐步運作、彼此關係、條件與工程後果」教完整。程式、操作和練習用來深化與檢查理解。目標朝中級維護能力建立，閱讀完成紀錄不等於取得職稱或已能維護任何公司系統。

**目前16個主題、123篇完整教材，共995題分層練習。** 第一輪重編原有83篇；本輪將剩餘六主題展開為40篇，新增320題，原有教材及網址保留。三位分工作者撰寫後互相審稿，交叉全文審查20篇代表章、檢查新增全部320題與解答，並獨立核算41項陌生輸入。全站15個C#教學專案、50組執行設定及123篇本機瀏覽檢查通過。具體發現、修正與驗證範圍見[本輪驗收說明](revision/remaining-topics/validation.md)；[第一輪驗收](revision/validation.md)保留為歷史紀錄。

公開發布與逐檔比對正在進行，結果將回填本輪驗收說明。

## 怎麼學

先選一個主題，依它自己的章節順序閱讀。每章說明必要前置概念，從原理進到完整例題、程式追讀與故障鑑別。基礎、應用和診斷練習附分段解答；先獨立回答，再比較推理過程。較長教材有章內目錄，手機也可直接跳到段落或練習。

時間分成「閱讀與追碼」「操作與比較」「作答與核對」三個範圍。閱讀按實際中文正文、英文詞和程式行估計，操作與作答按章內任務估計；尚未經個人計時校準，初次安裝工具另計。不要把估計高值視為必須坐滿的課時。

完成紀錄只存目前瀏覽器，舊版已完成標記沿用。教材重寫後若要重讀，可取消標記再重新標記；清除瀏覽器資料或換裝置不會自動同步。

## 如何驗證教材

第一輪基準是重編前版本45c87ef，本輪基準是前83篇完成後的54a9ecd。兩輪分開保留證據：第一輪比較全文重寫，本輪驗證新增六系列並確認原83篇未被改動；原有主題ID與網址保持一致。先檢查每章需要的能力，再由分工作者重寫，另一作者審查代表章的前置、推導、算式與陌生題，修正後統一驗收。

驗證分為不同證據：人工審稿看正文能否支撐理解與解題；C#模型檢查預測與不變條件；合成PCAP檢查原始欄位與資料一致性；網站測試檢查實際呈現、導航、下載、解答與進度。篇幅、題數、結構計量只是防止漏寫的警戒，不能替代內容審查。

完整數據在[重編紀錄](revision/README.md)，每個主題有作者檢查與交叉審查紀錄，明確區分實際執行和紙上判讀。後續仍需使用者按理解與計時回饋，校正節奏及難度。

## 教學模型與公司實際系統的界線

C#專案以.NET 10 Console、標準函式庫為獨立練習環境；它們是自行建立的Lab型別。真實Ozeki API片段另標來源與版本，未取得公司DLL，沒有在實際SDK編譯。公司既有.NET Framework可能不支援相同API，不能直接貼回去。

封包、紀錄、ICD和設備卡為合成或虛構教材，不含公司流量。軟體模型不能驗證接線、電平、聲卡、RF發射或廠商內部執行緒。RCSCall／iCallAPI的實際關係、部署拓撲與設備設定，仍要由授權原始碼及對應文件確認。工作筆記`對話.txt`沒有放進公開儲存庫。

## 本機開啟與維護

網站只有靜態HTML、CSS、JavaScript及JSON，沒有登入、伺服器或付費服務。GitHub Pages發布`main`分支的`/docs`。

```bash
python3 -m http.server 8000 --directory docs
```

Windows可用`py -m http.server 8000 --directory docs`，再開`http://localhost:8000/`。直接雙擊HTML可能無法載入JSON。

| 重要檔案／資料夾 | 用途 |
| --- | --- |
| docs/content/catalog.json | 主題、章節順序、狀態、簡介及分項時間 |
| docs/content/lessons/ | 一篇一個JSON，存正文、例題、練習、解答與來源 |
| docs/assets/diagrams/ | 原創SVG圖；不能把教學圖當真實拓撲 |
| docs/assets/labs/ | 原始碼、合成封包、操作說明與可下載專案ZIP |
| docs/app.js、docs/styles.css | 共用呈現與版型，新增章節通常不用改它們 |
| 課程地圖.md | 各主題邊界、完整章節與學習成果 |
| revision/ | 重編基準、共同規格、內容量測與審查證據 |
| tools/audit_content.py | 唯讀量測；--finalize在全部可閱讀章節結構通過後同步時間與目錄 |
| tools/package_labs.py | 打包原始碼，排除bin／obj與可執行檔 |
| tests/smoke.cjs、tests/browser.py | 資料／呈現互動檢查與選用的真實瀏覽器檢查 |

新增章節：先在catalog加入穩定ID與planned狀態，再依[教材規格](revision/authoring-standard.md)撰寫`<topic>--<chapter>.json`。內容審查、相關模型與網站驗證通過後才改成ready。新增主題則建立自己的目錄，不必變更其他主題順序。

基本檢查：

```bash
node --check docs/app.js
node tests/smoke.cjs
python3 tools/audit_content.py
```

瀏覽器檢查需另安裝Playwright與Chromium，開本機伺服器後執行`python tests/browser.py http://localhost:8000/`。C#教學專案解壓後依各自README執行；網站閱讀本身不需安裝.NET。驗證時在暫存資料夾編譯，避免把bin／obj發布。

下一步是以讀者回饋補強仍不清楚的觀念、校準時間，再依需要新增主題或深入章節。公司相關內容需要真實文件才能映射，不預先替未知系統定義架構。
