# 知識航線：可擴充的個人學習網站

**公開網站：** https://jason033.github.io/ICS_learning/  
**GitHub 儲存庫：** https://github.com/Jason033/ICS_learning  
**發布來源：** `main` 分支的 `/docs`，GitHub Pages 已啟用。

這個專案讓使用者依主題學習通訊、程式與設備知識，目標是逐步具備維護系統與分析故障的能力。每個主題有自己的章節順序；只有內容確實相關時才連到另一個主題。未來可以加入任何新領域，不必放進通訊系統的分類。

網站已完成可使用的第一版。首頁列出 16 個獨立主題；〈電腦網路〉10 篇、〈Wireshark〉8 篇、〈Ozeki API〉7 篇、〈RS-232 與設備介面〉7 篇、〈無線電通訊〉8 篇及〈PTT 與設備狀態〉8 篇教材已完整可讀，其餘清楚標示「規劃中」。教材有學習目標、白話說明、圖解、練習與可展開的解答。教材狀態與實際內容一致；「列在目錄上」不等於「教材已完成」。

## 已確認的需求與教材界線

- 主要給使用者自己使用；內容從基礎循序教起。使用者對 IP、Port、TCP／UDP、Socket 已有部分理解，但還需要把概念串成整體。
- 使用者指定需求並檢視內容，助手負責製作與維護。第一版採圖文教材、練習與解答。
- 目前學習範圍涵蓋網路、Socket、Wireshark、VoIP／音訊、Ozeki API、ICS／RCS 程式閱讀、RS-232、無線電、PTT、可靠性、Windows／Linux、衛星與多鏈路、DSP／SDR、資安及綜合故障分析。詳見 [課程地圖](課程地圖.md)。
- 教材區分通用原理、標明假設的教學例子，以及使用者提供並確認過的實際系統資訊。更新的 `對話.txt` 用作工作背景；裡面先前助手推測的呼叫順序或設備行為，不會被寫成已證實的公司架構。
- 新增大主題時，沿用網站版型並建立自己的章節目錄；不要求修改其他主題的教材或順序。

## 目前可以怎麼使用

進入首頁後選一個主題，從該主題自己的目錄挑選章節。讀完圖文可先回答練習，再展開解答。讀畢可以按「標記為已完成」；完成紀錄只保存在目前瀏覽器，換裝置或清除瀏覽器資料後不會保留。首頁搜尋可找主題或章節名稱。

〈電腦網路〉已完成一套約 **400 分鐘、10 篇**的教材，從最初的請求與回覆，依序學位址端點、Ethernet／MAC／ARP／VLAN、子網與路由、TCP／UDP、DNS／DHCP／NAT、單播／廣播／群播、MTU／QoS、效能指標，最後用整合故障案例練習定位。每篇有目標、白話說明、圖解或表格、至少 5 題練習與解答、重點回顧和公開技術來源；第一篇另有可在自己電腦操作的本機小實驗。教學位址、封包與設備情境明確標成模擬，沒有宣稱是公司系統。可從[網路主題頁](https://jason033.github.io/ICS_learning/#/topic/networking)依序進入。

〈Wireshark〉也已完成約 **355 分鐘、8 篇、48 題練習**的教材，從安裝與開檔、三個檢視區塊、兩種篩選、Follow Stream 與統計視窗，進到 TCP 故障、SIP／SDP、RTP 分析和封包對時。每篇都連到對應的[合成教學 PCAP](docs/assets/labs/README.md)，可在桌面 Wireshark 直接開啟；也有自製三區塊示意圖。PCAP 全由程式產生，不含公司流量。可從[Wireshark 主題頁](https://jason033.github.io/ICS_learning/#/topic/wireshark)進入。

〈Ozeki API〉已完成約 **345 分鐘、7 篇、50 題練習**的教材：辨認 SDK 與範例包裝類別、查產品版本與方法來源、追註冊、撥接事件、雙向媒體、事件與資源清理，最後以四個虛構故障案例整合練習。每篇附 Ozeki 官方資料入口，圖與紀錄皆為自製教學模型；未得到實際 SDK 版本、授權原始碼與部署證據前，不宣稱公司使用哪個 API 或如何呼叫。可從[Ozeki 主題頁](https://jason033.github.io/ICS_learning/#/topic/ozeki)進入。

〈RS-232 與設備介面〉已完成約 **330 分鐘、7 篇、50 題練習**：先分清 COM 埠、UART、RS-232 與設備命令，再學電氣與接線文件、8N1 等參數、文字與二進位訊息、檢查碼、逾時、串列工具、RS-422／RS-485，最後以五個虛構案例整合除錯。三張圖與 Device-Lab-A／B／C 都是自製教學材料；另有可下載的 [pySerial 軟體回環小程式](docs/assets/labs/serial-loopback.py)，不用實體設備即可觀察分段讀取與逾時。回環不能驗證線材或設備，實際 pinout 和安全條件仍須以授權設備手冊為準。可從[RS-232 主題頁](https://jason033.github.io/ICS_learning/#/topic/serial)進入。

〈無線電通訊〉已完成約 **420 分鐘、8 篇、65 題練習**：由控制、音訊與射頻的分工開始，學頻率／通道／頻寬、AM／FM 與數位調變、功率與天線、RSSI／SNR／BER／PER、收發方向與中繼台、可比較的量測紀錄，最後用六個虛構案例練習排查。兩張自製圖與所有 Radio-Lab 案例只作教學，不代表公司設備或可操作的發射設定。可從[無線電主題頁](https://jason033.github.io/ICS_learning/#/topic/radio)進入。

## 本機開啟

在本資料夾執行：

```bash
python3 -m http.server 8000 --directory docs
```

Windows 若使用 Python Launcher，可改用 `py -m http.server 8000 --directory docs`。接著在瀏覽器開啟 `http://localhost:8000/`。網站使用本機伺服器載入 JSON；直接雙擊 `index.html` 可能受到瀏覽器檔案存取限制。

## 放到 GitHub Pages

網站使用原生 HTML、CSS、JavaScript 與 JSON，沒有套件安裝或建置步驟。`docs/` 是可直接發布的網站目錄。

1. 若要建立另一份網站，先建立 GitHub repository，將本專案資料夾中的檔案放在儲存庫根目錄。
2. 在 repository 的 **Settings → Pages**，選擇 **Deploy from a branch**、`main` 分支及 `/docs` 資料夾，儲存設定。
3. 等待 GitHub 顯示網站網址，再用瀏覽器測試首頁、主題頁與章節頁。專案型 Pages 網址一般會包含 repository 名稱；本站採雜湊網址，章節連結也能在該路徑下運作。

本專案已發布在上方所列網址。後續更新公開內容前，請檢視教材與檔案，避免將公司或廠商非公開資料放進公開儲存庫。GitHub Pages 的[官方發布說明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)可作設定參考。

## 怎麼新增或修改教材

網站內容分成目錄、各篇教材與可重用資源：

```text
docs/
├─ index.html                網站入口
├─ styles.css                共用外觀
├─ app.js                    導覽、教材顯示與本機完成紀錄
├─ content/
│  ├─ catalog.json           所有主題與章節的清單、順序及狀態
│  └─ lessons/
│     └─ 主題代號--章節代號.json   每篇可閱讀教材
└─ assets/
   ├─ labs/                  可下載的 Wireshark PCAP 與串列軟體回環程式
   └─ diagrams/              自製示意圖
```

- **新增主題**：在 `catalog.json` 的 `topics` 清單加一個主題，設定不重複的 `id`、標題、說明與自己的 `chapters`。不需要修改現有主題。
- **新增章節**：在所屬主題的 `chapters` 加入章節資訊，並建立 `docs/content/lessons/主題代號--章節代號.json`。教材完成後把章節 `status` 設為 `ready`；仍在規劃則設為 `planned`，不建立空白頁。
- **章節格式**：參照現有 JSON，包含 `intro`、`goals`、`sections`、`exercises`、`recap`、`sources`。完整教材可加入 `plan` 學習時間安排與 `resources` 下載檔。段落可使用 `paragraphs`、`flow`、`bullets`、`steps`、`table`、`code`、`image`、`note`；網頁會自動套用共用版型。目錄中的 `contentType` 設為 `full` 或 `sample`，與教材完成程度一致。
- **保持連結穩定**：`id` 不跟隨顯示順序變動。調整章節位置只移動清單項目，不更改既有 `id`。
- **交叉引用**：只在教材確實需要其他主題的概念時加入連結或簡短提示。每個主題的入門章節應能獨立閱讀。

## 設計與驗證方式

基準是使用者已認識部分名詞，但尚難把它們連成完整流程。網路主題先用一次請求作共同觀察例子，再分章改變一個重點：端點、鏈路、路由、傳輸、輔助服務、群播、封包大小與效能。每篇用模擬案例比較「正常／異常」或「觀察前／後」，以練習檢驗讀者能否說清楚證據支持什麼、還缺什麼，以及下一步要查哪裡。最後一篇把前面所學放進多組整合故障案例。Wireshark 主題以同一批已知封包作基準，逐章改變觀察工具：列表／細節、篩選、串流、統計、SIP／RTP，再比較「能看到的封包」與「程式或設備是否完成」之間的證據差距。Ozeki 主題以官方範例的角色與事件為基準，逐章改變追查位置：文件／版本、註冊、通話、媒體、清理與綜合症狀；用自製時間線比較操作、SDK 回報、SIP／RTP 和裝置證據，檢驗讀者能否標出已知、未知與下一個檢查。串列主題以三張明確標示為虛構的設備卡為基準，逐章只改一個檢查面向：電氣與接線、字元設定、訊息內容、工具觀測、介面類型；用原始 TX／RX 位元組及軟體回環比較「本機有送出」「收到回覆」「設備真的完成」的證據差距。無線電主題以虛構的 Radio-Lab 測試紀錄為基準，分別比較控制、音訊、射頻與對端觀測；逐章增加頻率、調變、功率、接收品質、收發方向及量測條件，最後用六個案例練習選擇下一個證據。PTT 主題以 Box-Lab-A～H 的虛構按鍵、控制、介面盒、設備與對端紀錄為基準，逐章增加狀態、忙碌條件、音訊前後時序及重連事件；比較相同操作在各觀測點能證明什麼，最後用六個故障案例練習定位第一個證據缺口。

目前沒有完成學習成效實驗，也沒有真實公司系統的測試結果。10 篇網路教材的驗證標準是讀者能正確說出請求與回覆路徑、判讀端點與下一站、區分傳輸確認與應用成功，並在故障案例中選出下一個證據；56 題練習提供自我檢查，尚待使用者實際學習後回饋。Wireshark 的驗證標準是讀者能自己開啟三份 PCAP、找出方向與端點、用正確篩選定位案例，並對 TCP ACK、SIP 200 OK、RTP 序號缺口提出不超出證據的結論；48 題練習提供自我檢查。Ozeki 的驗證標準是讀者能辨認範例自寫方法與 SDK 方法、核對實際版本，並在四種虛構故障中選出下一個證據；50 題練習供自我檢查。串列主題的驗證標準是讀者能分清電氣、字元設定與設備命令，算對虛構框架的長度和檢查碼，解釋部分讀取及逾時，並在五個案例中選出下一項可驗證證據；50 題練習供自我檢查。無線電主題的驗證標準是讀者能分清強度、品質、錯誤率與發射狀態，對同條件數值做基本換算，並在六個虛構案例中選出最能區分候選原因的下一步；65 題練習供自我檢查。PTT 主題的驗證標準是讀者能將按鍵、請求、設備 TX、音訊及對端接收分開，辨認 COR／COS、忙碌鎖定與特定系統 Grant 的適用範圍，並在六個虛構案例中選出下一個觀測；65 題練習供自我檢查。Ozeki 具體 API 需依使用版本核對，設備狀態、RS-232 接線、無線電實測與 PTT 行為需依授權文件及實測確認。Wireshark、SDK 和硬體實驗需要相應的桌面工具或測試環境，網頁提供步驟、說明與解答。

開發檢查涵蓋全部 48 篇可讀教材的 JSON 解析、目錄對應、學習時間與練習數、表格欄數、資源檔與示意圖存在、JavaScript 語法、頁面導覽及本機 HTTP 供檔。串列與無線電新教材共 15 篇、89 段教學、115 題練習；五張 SVG 已完成 XML 解析，24 個相關網站檔案已由本機 HTTP 讀取並與磁碟逐位元組比對。串列的 pySerial `loop://` 範例已實跑，驗證四個位元組分兩次讀回、逾時後回空。Wireshark 的三份合成 PCAP 另由獨立程式驗證檔案格式、時間、IP／TCP／UDP checksum 與預期封包。PTT 新教材共 8 篇、50 段教學、65 題練習，四張 SVG 已完成 XML 解析；其內容、目錄、時間、題目與路由已通過本機檢查，15 個相關網站檔案已由本機 HTTP 讀取並與磁碟逐位元組比對。GitHub Pages 已成功建置本次 PTT 教材提交 `098df89`；公開首頁、程式、目錄、八篇 PTT 教材及四張圖等 15 個檔案皆可讀取，與提交檔案逐位元組一致。先前串列與無線電的 24 個相關公開檔案也已完成相同驗證。

這些檢查只證明教材結構、公開檔案與虛構例子一致，不能證明真實設備與公司系統行為。此環境沒有使用者的 Ozeki SDK、PBX、無線電設備或射頻儀器，也沒有做實體 RS-232 接線測試；Wireshark PCAP 尚待使用者在自己的桌面版本打開確認解析畫面。學習成效與使用者常用手機的實際閱讀感受也尚待回饋。
