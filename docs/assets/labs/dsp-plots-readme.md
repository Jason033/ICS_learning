# DSP圖表的來源、單位與重建

這兩張科學圖是合成數學資料，不是設備量測。正文先教公式與四點／八點代表值，圖只幫助看見同一個機制。沒有麥克風、RF、公司流量或未知檔案。

`dsp-four-point-dft.svg` 左圖是fs4sample/s的四點[1,0,-1,0]，實際時間0、.25、.5、.75秒；右圖是正DFT未除N的複數長度[0,2,0,2]。k是頻率bin索引，不能將右圖與左圖的同一行索引當成相同物理時刻。k1是+1Hz、k3是−1Hz，兩者共同表示實數cos。振幅為無單位正規化量。

`dsp-aliasing-samples.svg` 兩曲線按`cos(2πft)`、幅1、phase0產生，頻率1k與7kHz。曲線是已知數學函數，不是從八個點重建出來的實測。黑點僅n0..7、fs8000的八份取樣，最後.875ms；兩曲線在這些點同值，因此取得後無法僅依這些樣本辨別原頻率。

`dsp-plot-data.json` 分開保存DFT輸入、時間軸、輸出係數及混疊兩份數列。正文是解釋與結論，JSON是完整代表點證據，兩者不可互相取代。

可選Python輔助：另在自己的環境安裝`matplotlib`，執行`python dsp-plot-diagrams.py OUTPUT_DIRECTORY`，會產生兩張獨立SVG和JSON。主C#專案不需要Python或外部套件。這次已在隔離Python依賴目錄實際重建，斷言核對DFT係數與八點相等，並看PNG預覽檢查軸、標籤、重疊與代表點。圖的字體用英文免依賴中文字型，網站附中文alt與完整caption。

圖形不證明真ADC抗混疊、噪聲、校準、GNU RadioGUI或RF可用。改公式輸入要連同單位、代表點和正文更新，不能只為好看隨意畫曲線。
