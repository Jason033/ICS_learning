# 無線電基礎數據模型

這個模型解決的是「能否把教材機制與數字親自復算」的問題。它是獨立 .NET 10 標準函式庫 Console project，使用固定或合成資料，不開啟設備介面。公司的舊 .NET Framework 程式不一定能直接使用相同 API。

在專案資料夾執行 `dotnet run -- all` 可看完整基準。逐章使用 `dotnet run -- path` 與 `dotnet run -- path --fault` 比較音訊 RMS；其他模式是 `parameters`、`modulation`、`budget`、`quality`、`duplex`、`measurements`、`diagnose`。最後一種也可用 `dotnet run -- diagnose --fault` 看一組控制與 RF 證據仍存在、音訊卻缺失的虛構資料。

`Program.cs` 是各項數值規則；`expected-output.txt` 保留已執行的基準輸出；`NuGet.Config` 清空外部套件來源，本專案不需要額外套件。

範例頻率/功率/調變/儀器條件全為數學假設，不能當可操作的公司或地區發射設定。數據對照見各章；每次先算、改一項、觀察、復原。PASS僅檢指定算式，不是設備或音質驗證。

每次實驗先寫下基準、唯一變因與預期，再修改輸入。Check 的常數是獨立手算預期；例如把 TX 線損從 2dB 改為 4dB，RX 預期從 −67dBm 改為 −69dBm，要一併更新檢查。不要改成與計算同一條公式來強行通過。完成變因後復原輸入與預期，再重跑基準。

基準中，800 個 8kHz 音訊樣本代表 100ms，正弦 RMS 約 0.353553；故障版本為零。16QAM 的 4800 符號/s 先得 19200bit/s，編碼率與其他開銷後依序是 14400 和 12960bit/s。鏈路預算 RX 為 −67dBm；20kHz 與 NF 6dB 的簡化噪底約 −124.9897dBm。Ready 前無緩衝的音訊區間拆為 40ms 早送與 160ms 有效，量測外部損失還原為 −13dBm。這些結果驗證的是規則、單位與對照設計。

作者在 .NET SDK 10.0.401 編譯並執行全部模式，零編譯警告與錯誤；另在暫存副本故意把 RMS 改成「先平均再平方」、把 BER 改成整數除法，兩個對應基準檢查都失敗，還原後編譯成功。這表示檢查能發現這兩種特定錯誤，不是證明任意程式錯誤皆可檢出。

機制包括：音訊與控制/載波不同；波長與ppm；符號/編碼率；dBm/link budget/VSWR；kTB/NF/SNR與BER/PER；PTT時間及中繼方向；測點外接損失與RBW。真實發射、量測接線、頻率授權、額定/保護與廠商特有指標需正式文件與授權測試。

下一步是用教材功能圖讀正式設備文件與既有程式，將真實欄位來源、模式與量測條件逐一對應。模型未模擬 RF 電路、實際解調、FEC、傳播環境或硬體門控，也未驗證任何公司正常值。
