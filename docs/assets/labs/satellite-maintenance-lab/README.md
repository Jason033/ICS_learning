# 衛星與多鏈路：獨立 C# 判讀模型

這個專案讓你把距離、單位、容量和切換狀態逐行追清楚。它不模擬真實衛星網路，也不連網、不控制路由、不呼叫公司裝置或 DLL。所有 `Lab` 型別都是自行建立的教學型別。

需要獨立的 .NET 10 SDK。這不是要求升級公司的 .NET Framework 專案。解壓下載包，在此目錄執行 `dotnet run -- all`；也可將 `all` 換成下表模式。專案只使用標準函式庫，`NuGet.Config` 沒有外部套件來源。

| 模式 | 輸入、規則與可以驗證的結論 |
| --- | --- |
| latency | 72000km、1000byte、1Mbit/s，分開算單向273ms與對稱回覆加業務576ms；500ms等待不足。 |
| budget | 40000km、12GHz及同參考功率帳；自由空間206.074825dB，餘量6.925175dB，額外8dB跨門檻。 |
| capacity | 200ksymbol/s、每符號2碼bit、編碼率3/4或1/2、payload比例0.8；240k與160kbit/s。 |
| queues | 2Mbit/s、RTT0.6秒的BDP150000byte；32kbyte視窗上界約426.667kbit/s；五秒積壓12500byte。 |
| health | 固定同一邏輯時鐘的快照；先排除過期／服務未證實，再按優先排序；連續miss在成功時重置。 |
| failover | 候選B準備、世代更新、路由與會話兩證據提交；舊事件與半完成準備不能改active。 |
| diagnose | 相同幾何的600ms排隊差、物理up不等於服務、1220byte內包加80超過1280MTU。 |

`expected-output.txt` 是在隔離副本使用 .NET 10.0.401 實際執行 `all` 的輸出；25 項機制檢查透過，再印整體完成。基線不透過固定印 `PASS` 假裝驗證：每個檢查比較實際計算或狀態結果，錯誤會非零退出。

先手推、再設中斷點、最後核對輸出。依章節只改一個輸入或守衛，儲存預期失敗並還原。例如移除 `Commit` 的世代檢查，舊事件就可提交而應使驗收失敗。不要刪除驗收來掩蓋修改後的不符合。章節提供變因與預期，這份專案保留原始基準。

模型採固定、簡化資料：連續平均佇列、不含真TCP壅塞控制；健康不是BFD協定；切換是單執行緒狀態模型，沒有OS/NAT/SIP；預算不做實際雨場或全年可用率預測。真實服務需另外取得授權裝置檔案、相同配置的觀測與代表業務結果。

重要檔案：`Program.cs` 是七模式與模型；`Lab.csproj` 指定獨立SDK與編譯檢查；`NuGet.Config` 限定無外部套件；`expected-output.txt` 是基線證據。教材與作者審查紀錄在網站及 `revision/satellite-review.md`。
