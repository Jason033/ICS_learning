# 從理解原理到維護程式：教學方案草案

本方案依2026-10-03訪談整理。學習目標與入口方式已有明確依據，以下課程安排是製作者提出的方案，不是已完成或已證明有效的教材。

## 要交付什麼樣的學習產品

讓一位稍懂C++、會條件和迴圈，但C#與通訊系統不熟的新人工程師，可以自行選一個主題，從必要的基礎開始理解。讀到中段時，能在腦中建立正常運作的流程；讀到深入部分時，能把文件、設定和程式放回這個流程，解釋不同條件的後果，逐步能分析及修改既有程式。

教材的進階來自理解能力增加，不是問題變難或名詞變多。每個主題的主線是：為什麼需要這項技術、它如何正常運作、各部分如何配合、怎麼對照程式與設定、如何依原理處理異常。

硬體內容支援軟體理解。需要認識訊號方向、介面用途、設定限制及設備能提供的資訊；不要求設計電路、天線或射頻系統，也不把深度數學推導當成軟體維護的入門門檻。

## 共同基礎如何提供

共同基礎是可選的小系列，供需要時查閱。每個主題開場只介紹理解當前內容必要的概念；若需要更深入基礎，連到具體章節並指出讀完後回到哪一步。不是只寫「先學C#」或要求先修完整個網路主題。

| 基礎系列 | 教什麼、怎麼接已有知識 | 主要使用位置 |
| --- | --- | --- |
| C#程式閱讀 | 從熟悉的條件和迴圈對照C#；逐步教變數與型別、方法及參數、陣列與集合，再到類別、物件、參考、介面、事件和錯誤處理。需要並行時才進到執行緒、Task與await。 | Socket、Ozeki、ICS整合、可靠性與程式除錯。 |
| 資料在程式與通訊中的表示 | 從已有的進位轉換接到bit／byte、文字編碼、數值範圍、位元組順序、資料欄位與訊息邊界；每項都給實際用途。 | 網路、Socket、串列、封包判讀和音訊。 |
| 程式在電腦上如何運作 | 從程式檔案與一次執行開始，介紹作業系統、程序、執行緒、記憶體、檔案、設備和服務的不同角色，再連到程式呼叫系統功能。 | Windows／Linux、Socket、裝置介接、並行和故障分析。 |
| 必要的數量與圖表閱讀 | 用「每秒多少資料」「等待多久」「輸入變大時結果如何改變」等例子教單位、換算、比例與輸入輸出關係。log已有初步理解，使用到相關表示時再接到意義，不要求重背抽象數學。 | 傳輸、音訊資料量、佇列、時間及品質指標。 |

數學函數與程式方法分開解釋。訪談中「比例、函數」未說清楚情境，不能由該回答推定學習者沒有相應能力。後續用具體例子檢查理解即可，不必另做一大份數學考試。

## 主題如何從入門走到深入

每個主題都有可辨識的學習階段；具體篇數在教學展開時決定。下表是能力與範圍安排，不是保留目前章名後填更多字。

| 主題 | 先建立的正常運作知識 | 再深入的軟體理解與維護能力 |
| --- | --- | --- |
| 電腦網路 | 程式交換資料的需求、兩端角色、資料表示、本地連接與設備分工；再逐步教地址、同網段與跨網段、IP／Port、TCP／UDP及常用網路服務。 | 能追一次資料交付，讀設定與路由，理解連線、傳輸和應用回覆的關係；再教子網、DNS／DHCP／NAT、群播、容量及傳輸條件，不先用故障表代替正常流程。 |
| Wireshark | 先認識抓包在流程中的觀測位置、工具畫面和一筆正常交換；逐步教封包列表、細節、原始資料及篩選。 | 能用問題選觀測點及欄位，對照資料重組、時間和程式紀錄；SIP／RTP判讀在相應概念補足後再進入。 |
| Socket程式 | 先教程式怎麼要求作業系統收送資料、Client／Server分工，再逐行讀正常連線與交換。 | 理解TCP訊息邊界、編碼與解析、讀寫返回值，再到等待、取消、斷線、重連和資源生命週期；每種程式假設先有概念依據。 |
| VoIP與聲音 | 先從聲音輸入與輸出、數位樣本和兩端通話需求開始，分清建立通話與傳送聲音。再教角色、SIP流程、SDP和RTP。 | 能讀媒體方向、音訊格式、資料量與播放條件，追從擷取到播放的正常鏈路，再分析單向或斷續語音。 |
| Ozeki API | 先教函式庫／SDK／API及C#物件使用方式；理解電話核心、線路、單通電話和音訊元件。 | 沿一通正常電話讀建立、設定、註冊、事件、通話與媒體連接，再教版本、訂閱、清理和多通電話的生命週期。型別與事件先教再用。 |
| ICS／RCS與廠商API | 先教畫面、功能邏輯、包裝層與外部API為何分工；以文件和小程式建立呼叫、資料、狀態與事件的關係。 | 能從入口追方法、參數和物件，讀API／ICD資料契約，理解命令、回覆和後續通知，逐步整理功能與依賴；公司實際關係須由對應程式確認。 |
| RS-232與設備介面 | 認識COM埠、串列傳送、電氣介面與設備命令的分工；教收送方向、參數、資料框架和一筆正常交易。 | 能讀設備文件、軟體設定、byte資料和解析程式，分析參數、格式、分段與等待；電氣規格只到能辨識相容性和限制。 |
| 無線電通訊 | 以圖解教聲音、電訊號、射頻、發射與接收，認識頻率、通道、頻寬、調變、收發方式和中繼的用途。 | 能理解設備參數及RSSI／SNR等資訊在描述什麼，對照軟體控制、音訊與設備狀態；不要求鏈路預算、天線或阻抗設計推導。 |
| PTT與設備狀態 | 從輪流說話的需求、按下與放開開始，教發話意圖、控制、TX／RX、音訊及介面盒的正常配合。 | 理解狀態轉換、忙碌、發話權與前後時序，再讀程式旗標、控制請求、設備回報和恢復流程。 |
| 可靠性與並行 | 先教工作如何開始、等待及結束，正常程式執行順序，再介紹多個工作交錯、共享資料和事件。 | 逐步理解逾時、取消、重試、重複工作、重連、佇列、資源所有權及同步；再讀UI等待、競爭和死結，避免只靠背修法。 |
| Windows／Linux觀測 | 認識程序、服務、帳號、裝置、端點與紀錄的角色，先觀察一個正常程式。 | 能把程序、資源、網路與裝置資訊放回功能流程，讀CPU／記憶體與時間變化，分清程式、作業環境及外部依賴。 |
| 衛星與多鏈路 | 認識衛星在通訊路徑中的角色、高延遲與品質變動的意義，以及主備鏈路如何支援同一工作。 | 能理解應用等待、連線恢復、鏈路選擇、切換及會話影響，讀相關程式與設定；不深入軌道幾何、射頻功率或硬體容量公式。 |
| 訊號、DSP與SDR | 用波形、樣本和圖示教時間、頻率、振幅、取樣、濾波與資料率；把FFT、I/Q、SDR元件先作為有明確輸入輸出的處理角色。 | 能追軟體中的樣本、格式、取樣率、處理順序、跨批次狀態與延遲，讀頻譜與品質資訊。核心不要求複數指數或DFT公式手算；深入數學只在具體軟體任務確實需要時另作選讀。 |
| 通訊資安 | 先理解身份、權限、信任與資料保護的不同問題，再教金鑰、憑證、TLS及媒體保護的正常用途。 | 能讀身份來源、憑證條件、配置、金鑰輪替和驗證順序，再理解輸入驗證、重放及稽核；不要求自行設計密碼演算法。 |
| 故障分析 | 以已學過的正常流程，教症狀描述、正常對照、觀察與假設的差別，以及如何選下一個檢查。 | 能從機制提出候選、用證據排除、跨程式與設備整理時間，再進行有限修正與回歸驗證。整合案例使用真正需要的前置，不當成全站正文的骨架。 |
| 概念地圖 | 教如何辨認角色、關係、控制和資料路徑，以及圖的不同尺度。 | 用已有知識整理一項功能的流程、程式位置、文件和未知，協助閱讀公司系統；不是要求一開始就懂完整架構。 |

硬體與DSP的縮減是調整學習終點，不是刪光原理。軟體必須知道的資料格式、訊號意義和處理後果仍需完整說明，必要時用少量具體數字建立直覺。

## 篇幅、順序與語氣

每篇承擔一個明確的理解任務，相關概念在同一條解說中逐步引入。若一篇需要多組未教過的知識才能成立，就拆成數篇或先補基礎，不用字數上限壓縮。

正文需要足夠空間說明：問題從何而來、角色做什麼、一步怎麼導致下一步、具體例子如何符合原理、換條件為何改變結果。實際篇幅會比摘要式寫法增加，但不設每章相同字數或相同題型配額。較長內容按概念段落分節，並有前後承接。

學習開場先交代本章在主題中的位置，回接讀者已學會的內容，再提出這章要理解的問題。程式、圖示和例子出現前要說明為什麼需要它們；圖中的新元素隨正文逐步解釋。練習安排在能支援作答的內容後，用來確認理解與推理。

正文面向學習者，不反覆記錄製作歷史或解釋「因為某次要求，所以加了這一項」。時間估計、開發驗證和來源管理保留各自位置，不占用教學主線。

## 網站如何支援學習

首頁保留獨立主題入口，另提供共同基礎查閱。每個主題有自己的入門到深入順序，清楚說明學完能理解什麼；不以章節數和下載包數作為主要價值介紹。

章節入口說明必要前置，提供具體補課位置。閱讀中遇到需要回看已教概念，可直接回到相關段落並返回當前位置。詞彙說明輔助查閱，不能用彈出定義代替正文推導。

教材、例題、練習與故障資料有清楚的角色。讀者首先進入教學正文；工具和原始碼在真正需要時呈現。後续擴充主題沿用這個資料與導覽架構，但教學內容不受固定段落模板限制。

舊網址及有用資源應保留兼容入口。拆分章節時可讓舊入口指向更新後的章節群，不能為了維持舊切分繼續把不適合的內容塞在同一篇。

## 第一組連續教材試寫

以網路入門三篇測試新的教學方式，先使用同一個簡單「向另一個程式取得資料」情境，讓角色和資料在三篇持續出現。

1. 兩個程式為什麼需要通訊：建立兩端角色、資訊需求、請求與回覆的正常順序。先用圖及具體訊息，不跳入Socket非同步程式。
2. 要交換的資料如何表示：從同一筆訊息教資料、bit／byte、文字與編碼的用途；已有進位知識在實際欄位中再運用，不先塞完整二進位解析器。
3. 一次本地通訊經過哪些地方：沿同一筆資料理解程式、作業系統、網卡和本地連接。角色逐步增加，地址的需要在有明確問題時引出，再接後續地址與交付章。

本組不宣稱已教完整網路，而是先確保入門能成立。後續再逐步教MAC／IP、同網段與跨網段、Port、TCP／UDP等。正式切分以寫作和審查後的連貫性決定；章名仍可調整。

## 如何判斷方案是否有效

先由內容審查者從訪談起點閱讀連續三篇，標記每個新概念在哪裡被教、每個推論用了哪些前文；不能預先使用專家知道但教材沒教的知識。另一項技術審查確認說明、圖和例子的正確性。

再以實際閱讀檢查：是否知道章節目的，能否用自己的話解釋主要角色，能否重述正常流程，能否用已教原理回答小幅變化。讀者不必一次全答對；讀不懂的原因需要具體追查，據此改正文、順序或呈現。

試寫通過後，才按同一原則展開主題。進入維護階段時再檢查故障候選、證據選擇和修正驗收。自動測試負責原始碼與網站正常，不能代替以上學習判斷。

本方案已用於三篇新版網路入門，正文與網站已整合，具體審查見[reader-review.md](reader-review.md)。其他主題及可選共同基礎尚未按本方案重編；三篇試讀不代表整個課綱已完成，實際學習效果仍需閱讀確認。
