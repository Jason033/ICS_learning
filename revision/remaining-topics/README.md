# 剩餘六個主題的完整教材

前一輪十主題83篇已完成第二版。這一輪延續相同要求：先建立完整基礎與機制，走向公司程式閱讀、維護與除錯；C#／.NET為主，Python輔助。使用者已明確確認完成六個主題的完整系列、約40篇並維持前次深度。既有六個未完成主題只有九個入口，按課程地圖展開40篇，原有網址保持可用。

## 範圍與分工

| 主題 | 篇數 | 為何分成這些章節 |
| --- | ---: | --- |
| Windows／Linux觀測 | 8 | 程序、服務、端點、裝置、紀錄及資源是不同證據層，需分開教清楚 |
| 衛星與多鏈路 | 7 | 路徑時間、品質容量、傳輸及切換有不同機制與驗收條件 |
| DSP／SDR | 8 | 先懂樣本與頻譜，再讀濾波、功率、符號和I/Q的資料處理 |
| 通訊資安 | 7 | 身分、權限、加密、信任、金鑰與重放不能用一個「安全」標籤代替 |
| 故障分析 | 6 | 教會重現、對照、證偽、時間線、分支實驗及修正驗收的方法 |
| 概念地圖 | 4 | 示範如何整理邊界、契約、追碼與可維護文件，不假定公司拓撲 |

三位作者各負責兩主題，之後交叉審查另一組作品。主代理負責範圍、目錄、跨主題一致性、模型／網頁／公開資源驗證。

## 驗收流程與限制

基準為54a9ecd的83篇教材及九個未製作入口；變因為六主題完整正文、例題、推理解答與獨立模型。依共同標準從定義和前置出發，再以兩個完整算例、讀碼、分支診斷及陌生題檢查理解。字數僅用來抓漏，不能代替內容審查。

作者核對官方來源與模型後，由另一作者讀代表章並獨立推算陌生題，所有明確問題修正及複核後才把目錄改為可閱讀。最後全站自動檢查、真實瀏覽器和公開檔案比對。不將合成資料或獨立模型當成公司SDK、Windows工具畫面、音訊設備或RF實測。

## 完成結果與證據位置

六系列40篇與320題均已完成，原83篇不變、原92個網址保留；全站123篇／995題。三組跨作者審查全文讀20篇代表章、檢查全部320題與解答、獨立核算41項陌生輸入；已發現的峰值、算例前提、程式契約及測試互相遮蔽等問題都已修正讀回。全站15個C#專案的50組執行設定成功，15份下載包來源一致，本機123篇實際瀏覽通過。篇數和字數僅防漏，不能保證學習成效或工程職等。
